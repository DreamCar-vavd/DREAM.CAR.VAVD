# Панель керування контентом DREAM.CAR.VAVD

Статус: **розділи «Автомобілі» + «Галерея (тексти)»** на спільній моделі
чернеток/публікації, з робочим hosted-адаптером GitHub (draft PR #26, не
змерджено). Повний аналіз: `report/35-admin-panel-stage3.md`.

---

## Дві адреси

| Адреса | Що це |
|---|---|
| **`/keystatic`** | редактор контенту. Тут заповнюють поля авто й робіт галереї, трьома мовами. **Зміни тут не потрапляють на сайт.** |
| **`/panel`** | панель публікації. Стан кожної картки, позначки мов, кнопки «Опублікувати зміни» / «Прибрати з сайту», стан збірки. |

## Модель

```
Keystatic (редагувати)  →  src/content/cms/{cars,gallery}/<id>.json   РОБОЧА копія
        │
        ▼
/panel «Позначити перевіреним» (UK / EN / RU)  →  src/content/cms/review-state.json
        │
        ▼
/panel «Опублікувати зміни»  →  src/content/cms/published.json   ПУБЛІЧНИЙ знімок
        │
        ▼
Vercel збирає  →  банер «✅ Поточний знімок в ефірі» (1–3 хв)
```

Сайт читає **лише `published.json`**. Тому редагування опублікованої картки
не змінює сайт, поки не натиснути «Опублікувати зміни»; нова картка невидима
до публікації; «Прибрати з сайту» / «Продано» лишають картку в панелі.

## Правило трьох мов

Опублікувати можна лише коли для кожної з UK/EN/RU: заповнені обов'язкові
поля (авто — назва + характеристики; робота — назва) **і** натиснуто
«Позначити перевіреним». Будь-яке редагування тексту скидає перевірку цієї
мови. Зміна спільної ціни / статусу / року **не** скидає переклади.
Перевірка діє на сервері (`/api/panel`), не лише вимкненою кнопкою; і ще
раз — під час `next build` (`src/lib/content/snapshot.ts`): непридатний
знімок валить збірку, Vercel лишає попередній деплой.

## Режими зберігання

| | Коли | Куди пише |
|---|---|---|
| **local** | `next dev` | файли на диску (атомарно) |
| **github** | деплой із `KEYSTATIC_STORAGE_KIND=github` | комміти через GitHub API токеном користувача, у гілку деплою; оптимістична конкурентність (409 → «оновіть сторінку») |

`/keystatic`, `/panel`, `/api/*` → **404** на деплої без
`KEYSTATIC_STORAGE_KIND=github`. Локальний файловий режим не має авторизації
й не може писати на serverless FS — його не можна виставляти публічно.

## Галерея

Редагується **текст** робіт (×3 мови: назва, короткий/докладний опис, вид
послуги, проблема → виконані роботи → результат, рік, посилання на відео,
перемикач CTA) **і фото** — той самий віджет, що в авто: додавання, головне
(перше), порядок перетягуванням/стрілками, підписи/alt, видалення. Робота
без фото не публікується. Завантаження відео**файлів** — не підключено.

## Перегляд чернетки на реальному сайті

`/panel` → «Переглянути чернетку на сайті» → відкриває публічні сторінки, що
рендерять **робочу версію** (ще не опубліковану), з жовтим банером. Вихід —
«Вийти з перегляду». Звичайні відвідувачі цього не бачать. Публічні сторінки
лишаються статичними.

На деплої (github-режим) перегляд показує стан **останньої збірки гілки** —
живі правки Keystatic видно після передеплою.

## Команди (розробнику)

| Команда | Призначення |
|---|---|
| `npm run dev` → `/keystatic`, `/panel` | панель локально |
| `npm run content:check` | перевірити, що `published.json` придатний (авто + галерея) |
| `npm run content:migrate` | (одноразово) перенести наявний контент — вже виконано |

## Увімкнення hosted-панелі (дії власника — report/35 §12)

1. **GitHub App** — Contents R/W, Pull requests R/W, **Deployments: Read**,
   Metadata: Read; install тільки на цей репозиторій.
   Callback: `https://dream-car-vavd.com/api/keystatic/github/oauth/callback`.
2. Vercel env (Production + Preview): `KEYSTATIC_STORAGE_KIND=github`,
   `KEYSTATIC_GITHUB_CLIENT_ID`, `KEYSTATIC_GITHUB_CLIENT_SECRET`,
   `KEYSTATIC_SECRET`, `KEYSTATIC_GITHUB_REPO_OWNER=DreamCar-vavd`,
   `KEYSTATIC_GITHUB_REPO_NAME=DREAM.CAR.VAVD`.
   (опц.) `PANEL_CONTENT_BRANCH` — окрема гілка для контент-коммітів.
3. Помічник — collaborator із роллю **Write** (не Admin); 2FA обом.
4. Рішення: приватність репозиторію (report/35 §6); гілка публікації для
   Production (§12 п.3).
5. Застосувати діф CI з report/34 §4 (крок `content:check`).

> У hosted-режимі код мосту `/api/panel`→GitHub **завершений** і покритий
> mock-тестами, але з реальним GitHub ще не перевірений — потрібен App.
