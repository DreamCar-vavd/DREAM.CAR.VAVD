# Фотографії послуг на публічній сторінці

**Що зроблено (П36 / задача 14:39).** Поле «Фотографії» у редакторі послуг
(Keystatic) вже було, але публічна сторінка `/[locale]/services/[slug]` їх не
показувала. Тепер показує — компонент `src/components/ServicePhotos.tsx`,
підключений у `src/app/[locale]/services/[slug]/page.tsx` під списком переваг.

## Поведінка

| Аспект | Реалізація |
|---|---|
| Пропорції | Сітка прев'ю — рівні плитки `aspect-[4/3]` + `object-cover` (як картки авто/галереї). У лайтбоксі — справжні пропорції фото (`object-contain`, `aspectRatio` з інтринсивних розмірів, які `getServicesMeta` читає через `imageSize()`) |
| Телефон | `grid-cols-2` (≥640px — `sm:grid-cols-3`); перевірено на реальному `window.innerWidth = 375` — без горизонтального прокручування, підписи переносяться |
| Немає фото | `ServicePhotos` повертає `null` — секції немає, порожнього блоку немає (перевірено на `detailing`, `photos: []`) |
| Підписи / alt | `caption` у Keystatic — одне поле (мовно-нейтральне), показується як є. Якщо порожнє — alt = «`<локалізована назва послуги>` — `<локалізоване «Фото»>` `<номер>`» (`servicePhotoAlt()`); слова беруться з `dict.carsForSale.photoAlt` тощо, тож текст завжди мовою сторінки |
| Лайтбокс | клік по плитці → модалка; `←/→` гортання, `Esc` закриває, фокус повертається на плитку; пастка фокуса через `useDialogFocusTrap`; лічильник `NN / NN` |
| Чернетка vs опубліковане | Сторінка бере фото з `getServicesMeta()` → `readSiteContent()`: у draft-режимі — робоча копія, без нього — `published.json`. Опубліковані шляхи вказують на **заморожені** копії (`…/<slug>/_pub/<hash>.<ext>`), тож правка фото в чернетці не змінює опубліковану сторінку — ні на цьому deployment, ні на наступному |
| Зникле фото | `onError` на `<Image>` ховає **саме цю** плитку (`markBroken`), решта лишається; секція не зникає. Резервний запобіжник — заморожені копії роблять цей випадок рідкісним |

## Заморожування опублікованих фото (задача 2026-09-09 §5–6)

Keystatic редагує **робочі** файли фото
(`…/<slug>/photos/<i>/image.<ext>`) — перенумерація змінює їх, видалення прибирає
один, обидва прямими комітами, яких панель не бачить. Раніше `published.json`
посилався на ці робочі шляхи, тож **наступний** deployment (будь-який коміт)
404-ив би зображення, яке власник не перепубліковував.

Тепер на «Опублікувати» кожне робоче фото копіюється, content-addressed, у
`public/images/cms/<kind>/<slug>/_pub/<sha256[:24]>.<ext>` — теку, якої Keystatic
не знає, — і в знімок іде **цей** шлях (`src/lib/content/panelStore.ts` →
`planFrozenMedia` → `writeFrozenMedia`).

**Помилка = публікація не відбувається (П39 §2).** Якщо вказане фото не читається
(відсутній файл, мережа, відмова доступу) або копію не вдалося записати —
`publishItem` кидає помилку **до** запису `published.json`. Попередній
`published.json` і його `_pub/` фото лишаються цілими. Необов'язкове незаповнене
фото (`image: ""`) — і далі no-op, не помилка.

**Визначення змін фото — за фактичною версією зображення (П39 §1).**
`/panel` (`inSyncIgnoringFrozenPhotos`) читає кожне робоче фото, хешує і звіряє з
ім'ям опублікованого `_pub/<hash>`. Заміна фото на інше за тим самим шляхом,
або перестановка (Keystatic перенумеровує файли) → «є неопубліковані зміни»,
яку власник публікує звичайною кнопкою. Байт-ідентичне фото → «синхронізовано»
(без фантомних змін). Кількість, порядок, підписи звіряються точно.

**Прибирання старих копій — окрема захищена дія (П39 §3).**
`publishItem`/`unpublishItem` **не** видаляють `_pub/` файли (авто-GC міг
перегнати паралельну публікацію й видалити потрібне фото). Кнопка «Прибрати
старі копії фото» на `/panel` (`cleanupFrozenMedia`, version-guarded по
`published.json`) прибирає файли, на які поточний `published.json` не
посилається. `publishItem` після запису знімка ще раз записує свої копії — гонка
з очищенням не лишить нове фото без файлу.

- Робочі файли `photos/*` лишаються — Keystatic далі ними володіє.
- Наявні 11 опублікованих авто/галерей заморожено разово
  (`scripts/migrate-freeze-published-photos.mjs`); скрипт ідемпотентний.
- `content-guard` (для `main`) працює як раніше — `_pub/…` шляхи проходять
  `MEDIA_RE` (`…/<slug>/_pub/<hex>.<ext>`).
- Ціна: git як сховище → заморожені копії важать ~стільки ж, скільки оригінали
  (одноразово ~31 МБ). Нового платного сервісу немає.

Те саме діє для фото авто, галереї та банерів — одна реалізація.

## Не змінено

`keystatic.config.ts` (поле фото як було), `publishedServices.ts` (уже віддавав
`photos` з розмірами), формат `published.json`, компоненти авто/галереї.
