# Фотографії послуг на публічній сторінці

**Що зроблено (П36 / задача 14:39).** Поле «Фотографії» у редакторі послуг
(Keystatic) вже було, але публічна сторінка `/[locale]/services/[slug]` їх не
показувала. Тепер показує — компонент `src/components/ServicePhotos.tsx`,
підключений у `src/app/[locale]/services/[slug]/page.tsx` під списком переваг.

## Поведінка

| Аспект | Реалізація |
|---|---|
| Пропорції | Сітка прев'ю — рівні плитки `aspect-[4/3]` + `object-cover` (як картки авто/галереї). У лайтбоксі — справжні пропорції фото (`object-contain`, `aspectRatio` з інтринсивних розмірів, які `getServicesMeta` читає через `imageSize()`) |
| Телефон | `grid-cols-2` (≥640px — `sm:grid-cols-3`); перевірено на реальному `window.innerWidth = 375` — без горизонтального прокручування, підписи переносяться |
| Немає фото | `ServicePhotos` повертає `null` — секції немає, порожнього блоку немає (перевірено на `detailing`, `photos: []`) |
| Підписи / alt | `caption` у Keystatic — одне поле (мовно-нейтральне), показується як є. Якщо порожнє — alt = «`<локалізована назва послуги>` — `<локалізоване «Фото»>` `<номер>`» (`servicePhotoAlt()`); слова беруться з `dict.carsForSale.photoAlt` тощо, тож текст завжди мовою сторінки |
| Лайтбокс | клік по плитці → модалка; `←/→` гортання, `Esc` закриває, фокус повертається на плитку; пастка фокуса через `useDialogFocusTrap`; лічильник `NN / NN` |
| Чернетка vs опубліковане | Сторінка бере фото з `getServicesMeta()` → `readSiteContent()`: у draft-режимі — робоча копія, без нього — `published.json`. Перевірено: правка фото в чернетці змінює **лише** draft-перегляд, опублікована сторінка того самого deployment не змінюється |
| Зникле фото | `onError` на `<Image>` ховає **саме цю** плитку (`markBroken`), решта лишається; секція не зникає. Перевірено: посилання на файл, якого немає на диску → плитка тихо зникає, без «битої картинки» |

## Межа: заміна/видалення фото між deployment'ами

Кожен Vercel-deployment — це один git-checkout: `published.json` і файли
`public/images/cms/services/<slug>/photos/<i>/…` там завжди з одного коміта.
Тож **на одному deployment** опублікована сторінка ніколи не ламається від
правок у чернетці.

Ризик — **між** deployment'ами: якщо власник у Keystatic видаляє/замінює фото
(Keystatic перенумеровує теки `photos/0,1,…` і **видаляє** старий файл своїм
комітом), а потім **не** публікує, то на наступному deployment опублікована
сторінка все ще посилається на стару теку → цей файл 404. Пом'якшення:

1. `onError` ховає таку плитку — сторінка лишається охайною, «битої картинки»
   немає.
2. Next кешує вже оптимізовані зображення (`.next/cache/images`), тож фактичний
   розрив видно не одразу.
3. **Правильна дія власника:** після будь-якої зміни фото натиснути
   «Опублікувати зміни» — новий `published.json` вказуватиме на нові теки, файли
   яких є в тому самому коміті.

Повне усунення (копіювати файли знімка в стабільну теку при публікації) — окреме
рішення; воно стосується так само авто й галереї, які вже мають цю саму
властивість, і в цю задачу не входить.

`photos` з розмірами), формат `published.json`, компоненти авто/галереї.
