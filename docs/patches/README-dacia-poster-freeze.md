# Патч: заморозити `video.posterSrc` для 2 наявних Dacia

**Статус:** підготовлено й перевірено, **НЕ застосовано**. Файл `dacia-poster-freeze.patch`.

## Що це

`dacia-sandero-2022` і `dacia-sandero-comfort-2019` у `published.json` мають
`video.posterSrc`, що вказує на **плоский робочий шлях** `…/photos/0/image.jpg`,
хоча саме фото 0 уже заморожене (`photos[0].image` = `…/_pub/<hash>.<ext>`).
Тобто постер — єдине опубліковане посилання на зображення, яке не проходить
через `_pub`. Якщо Keystatic перенумерує/видалить фото 0 без повторної
публікації авто — постер може 404-нути.

Патч переставляє `posterSrc` цих 2 записів на **ту саму `_pub`-копію**, на яку
вже вказує `photos[0].image`.

## Чому це безпечно

- Змінює **лише** 2 рядки `published.json` (2 значення `posterSrc`). Нічого
  більше — ні `publishedAt`, ні робочі файли, ні інші записи. Перевірено:
  `JSON.parse` до/після відрізняються рівно цими 2 полями.
- Ціль кожного `posterSrc` **байт-ідентична** поточному файлу постера
  (`cmp` → identical; sha256 збігається; 24-hex префікс імені `_pub`-файла ==
  перші 24 hex sha256). Тобто візуально постер не зміниться.
- `_pub`-копії вже існують у репозиторії (створені при останній публікації
  кожного авто).
- Після патчу `/panel` показує всі 3 авто **`in-sync`** (звірено локально
  `getPanelData` на `LocalFsStorage`): новий дифер порівнює `_pub`-постер із
  робочим фото 0 за git blob-id — байти однакові → без фантомної «є зміна».
- `tsc` 0, `panelStore.test.ts` 85 pass, кожне опубліковане локальне
  посилання має файл (53/53).
