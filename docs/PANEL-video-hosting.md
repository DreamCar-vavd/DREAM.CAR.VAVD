# Відео авто: локальний режим і хостинг (Vercel Blob)

## Чому не через серверний маршрут

Vercel обмежує **тіло запиту Serverless/Edge Function до 4.5 МБ**
([docs](https://vercel.com/docs/functions/limitations#request-body-size)).
Відеоролики огляду — десятки-сотні МБ, тож вони **не можуть** проходити через
`/api/panel/video`. Тому:

| Режим | Як | Обмеження |
|---|---|---|
| Локальний (`next dev`, немає `BLOB_READ_WRITE_TOKEN`) | браузер `PUT`-ить байти на `/api/panel/video`; сервер робить magic-byte sniff і пише у `public/uploads/videos/` (git-ignored) | ліміту 4.5 МБ немає (це `next dev`, не Vercel); файли лише на цьому Mac |
| Хостинг (є `BLOB_READ_WRITE_TOKEN`) | **клієнтське завантаження Vercel Blob**: `upload()` з `@vercel/blob/client` обмінюється коротким токеном із `/api/panel/video` (`handleUpload`), далі браузер стрімить файл **напряму в Blob**, повз функцію | розмір ≤ 200 МБ (ліміт задає токен); тип лише `video/mp4` / `video/webm` |

## Що реалізовано

- `src/lib/media/videoStore.ts`:
  - `LocalVideoStore` — повний цикл (create → receive+sniff → list → head → remove), temp+rename.
  - `BlobVideoStore` — `list()` / `head()` / `remove()` через `@vercel/blob`
    (`list`/`head`/`del`), читає `BLOB_READ_WRITE_TOKEN` **на момент виклику**;
    без токена — `VideoStoreNotConfiguredError`, **ніколи** не пише в репозиторій.
  - `tokenRulesFor(pathname)` — правила видачі токена (префікс `panel/videos/`,
    лише mp4/webm, `maximumSizeInBytes = 200 МБ`, `addRandomSuffix`) — **юніт-тест**.
- `/api/panel/video` `POST` — дві гілки за `body.type`:
  - `blob.*` → `handleUpload({ onBeforeGenerateToken, onUploadCompleted })`;
    `onBeforeGenerateToken` **повторно перевіряє сесію** (`getStorage()`) і
    `tokenRulesFor(pathname)` перед видачею токена;
  - інакше → локальний «create upload target».
- `/panel/video` UI — `VideoUploader` гілкується за `mode`:
  - `blob` → `upload(pathname, file, { access:'public', handleUploadUrl,
    onUploadProgress, abortSignal })` — **прогрес, скасування (AbortController),
    повтор, помилки**;
  - `local` → XHR `PUT` з `xhr.upload.onprogress` + `xhr.abort()`.
- **Звʼязок із матеріалом**: після завантаження показується URL і покрокова
  інструкція вставити його в поле «Відео» авто в Keystatic (саме `video.src`
  публікується). Список завантажених відео позначає, яке авто кожне використовує;
  видалити файл, що **використовується**, з панелі не можна; осиротілі не
  видаляються автоматично.
- Гейт публікації: режим `hosted-file` без `src` або з небезпечним `src` →
  **блокер** (`carsGate`, `snapshot`, `content-guard`). Видалення/заміна відео в
  чернетці не чіпає опублікований знімок (у ньому власна копія `video.src`).

## Стан

- **Код** — реалізовано.
- **Контракт** — перевірено через юніт-тести (`tokenRulesFor`, `blobPathnameFor`,
  `remove()` відхиляє не-URL, адаптер кидає NotConfigured без токена) і локальний
  прогін гілки `body.type` у маршруті.
- **Реальне сховище Blob — НЕ підключено.** Живу інтеграційну перевірку
  (справжнє завантаження ролика на Preview) можна зробити лише після видачі
  `BLOB_READ_WRITE_TOKEN`. Це **не** «жива перевірка Blob».

## Приватність чернеткових відео — компроміс для рішення власника

**Так, тут є компроміс, і його треба ухвалити ДО створення Blob-сховища.**

Завантажене відео зберігається як `access: "public"` блоб. Наслідок: **файл
доступний за своїм URL одразу після завантаження — ще до того, як картку авто
опубліковано**. URL містить довгий випадковий суфікс (`addRandomSuffix`), тож
його **неможливо вгадати** і він **не індексується** (ніде публічно не
згадується, доки картку не опубліковано). Але це **не контроль доступу** —
хто має URL, той відкриє відео. «Немає посилання в каталозі» захистом не є.

| Варіант | Що дає | Ціна |
|---|---|---|
| **`public` (обрано)** | простий публічний site після публікації; чернетка = «нелистований» URL (як приватне відео на YouTube) | чернеткове відео технічно доступне за URL до публікації |
| `private` + підписані URL | справжній контроль доступу до чернетки | публічний сайт теж має щоразу отримувати підписаний URL (термін дії, кеш) **або** копіювати відео в public при публікації — окремий етап розробки |

**Оцінка:** відео авто — це **промо-контент огляду**, який власник і так хоче
зробити публічним; чутливих персональних даних у ньому немає. Для такого
контенту «нелистований public URL» — прийнятний компроміс. Якщо колись у відео
може бути щось приватне — потрібен `private`-варіант (окремий етап).

**Рішення власника:** підтвердити `public` для відео авто, або замовити
`private`-варіант перед створенням сховища.

## Що потрібно від власника

1. Vercel → проєкт `dream.car.vavd` → **Storage** → Create → **Blob** → access
   **Public** (готове відео на сайті публічне). Прив'язати до проєкту для
   середовищ **Preview** і **Production** (Development — за бажанням для
   локальних тестів).
2. Vercel сам додасть env `BLOB_READ_WRITE_TOKEN` у вибрані середовища.
   Вручну нічого вставляти не треба; **redeploy** гілки після цього.
3. Перевірка: `/panel/video` на Preview → завантажити тестовий ролик → має
   з'явитися в списку; вставити URL у поле «Відео» авто → чернетка показує відео.

## Витрати

Vercel Blob має безкоштовний обсяг; ліміти сховища й трафіку **не перевірено в
цьому завданні** — звірити на `https://vercel.com/pricing` перед завантаженням
багатьох роликів. Кілька відео огляду можуть вийти за безкоштовний обсяг.
