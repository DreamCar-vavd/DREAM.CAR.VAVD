## C. Подвійне натискання під час запису й під час оновлення

**Середовище:** local `next dev` (:3025), стаб робить запис повільним (1.2 с) ·
**код `21d9db4`**. Лічильник — POST-запити до `/api/panel`.

```
3× швидкі кліки на «Прибрати старі копії фото»   → 1 POST
2× клік «Підтвердити — прибрати N»               → +1 POST  (2 всього: 1 dry + 1 confirm)
після confirm+refresh, 2× клік на (розблоковану) кнопку → +1 POST  (новий сухий прогін — ЧИТАННЯ)
```
Висновок: **дублюючого запису немає.** Синхронний `useRef`-guard + `disabled`
блокують повторний клік до наступного рендера й під час refresh.

## Preview — звичайний цикл очищення

**Середовище:** Vercel Preview (branch alias), авторизована сесія власника ·
**код `21d9db4`** (deployment `21d9db4bf`)

```
POST /api/panel {action:cleanup-frozen-media, confirm:false}  → count 2, headSha 2c4720e9b…
POST /api/panel {action:cleanup-frozen-media, confirm:true}   → «Прибрано 2 стар(у/і/их) копі(ю/ї/й) фото. Зміни в гілці після наступної збірки.»
POST /api/panel {action:cleanup-frozen-media, confirm:false}  → «Зайвих копій фото немає — усе прибрано.»
```

На GitHub: обидва файли → 404; **один** атомарний коміт `866b271` «panel: drop 2
unreferenced media file(s)» лише з тими 2 шляхами. Чистий діф
`21d9db4..866b271` — **порожній**.

## Залишок (для наступного чату)

- Знімки саме **Preview** для станів: очікування / «триває довше» / конфлікт /
  невизначений запис / «Перевірити результат» → результат. (Сесія власника у
  фоновій вкладці періодично «замерзає» — надійніше Playwright проти Preview
  або попросити власника тримати вкладку активною.)
- «Звичайний цикл» на Preview через **кнопку в UI** на погодженому
  `zzz-test-panel` (не лише `POST`), з повним прибиранням.
