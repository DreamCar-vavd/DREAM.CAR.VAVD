# Протокол реальної hosted-перевірки панелі

Виконується **після** погодженого підключення GitHub App
(`docs/PANEL-hosting-and-approvals.md` §3), на **Preview**-деплої гілки
`codex/admin-panel-spike`. Production і `main` не залучені.

**Не активувати** workflow, що переносить контент у `main`
(`content-guard.yml`), до завершення цього протоколу — перша перевірка має
лишитися повністю ізольованою (`PANEL_CONTENT_BRANCH` веде в окрему гілку, не
в `main`).

### Крок 12 — чому це рішення політики, а не дефект

`DREAM.CAR.VAVD` — **публічний** репозиторій. Це означає, що вміст будь-якого
файлу на будь-якій гілці (включно з неопублікованими чернетками в
`src/content/cms/`) **вже читається будь-ким напряму на github.com або через
GitHub API, без жодної автентифікації** — незалежно від того, що робить наш
власний UI. Блокування перегляду `/panel`-дашборду чи draft-preview для
видаленого колаборатора **не сховає ці дані** — воно лише прибере зручний
перегляд у НАШОМУ інтерфейсі для когось, хто й так технічно міг би прочитати
той самий файл напряму в репозиторії.

Тому це вибір поведінки продукту, не помилка:
- **Варіант А (поточний стан):** перегляд `/panel`/draft-preview лишається
  доступним для будь-якого колишнього/поточного підписаного користувача;
  реальний захист — на рівні ЗАПИСУ (редагування, публікація, заявки), де
  GitHub і наш код і так відхиляють дію без чинних прав.
- **Варіант Б:** додати ту саму перевірку `assertWriteAccess()`, що вже
  захищає `/panel/leads`, і до `/panel`-дашборду та `/api/panel/preview` —
  дасть однакову поведінку UI для всіх трьох сторінок, але **не додасть
  реальної конфіденційності**, бо дані лишаються публічними в самому
  репозиторії.

Жоден варіант не «ховає файли, які й так доступні у публічному GitHub» —
різниця лише в тому, чи наш власний інтерфейс імітує обмеження. Рішення, який
варіант відповідає намірам власника, приймає власник; до цього крок 12
лишається ⚠️, не ✅.

**Залишковий блокер (кроки 3 і частина 12):** потрібен реальний, живий сеанс
браузера облікового запису **без** доступу Collaborator (не фейковий токен) —
у підключеному до цього сеансу браузері є лише сесія власника (`DreamCar-vavd`);
другий тестовий акаунт (`VOLODYMYR-LUCKY`) залишається на окремому пристрої
власника. **Одна необхідна дія власника:** відкрити на тому пристрої з
`VOLODYMYR-LUCKY` (той самий, без Collaborator-доступу) `/panel/leads` і
`/keystatic` на Preview, надіслати скріншоти обох результатів.

Після успіху — окреме рішення власника про активацію `content-guard.yml` у
`.github/workflows/` + ruleset (той самий документ §1.5).
