# Протокол реальної hosted-перевірки панелі

Виконується **після** погодженого підключення GitHub App
(`docs/PANEL-hosting-and-approvals.md` §3), на **Preview**-деплої гілки
`codex/admin-panel-spike`. Production і `main` не залучені.

**Не активувати** workflow, що переносить контент у `main`
(`content-guard.yml`), до завершення цього протоколу — перша перевірка має
лишитися повністю ізольованою (`PANEL_CONTENT_BRANCH` веде в окрему гілку, не
в `main`).

**Блокер А (кроки 3, 12-жива-частина) — єдиний залишковий:** потрібен
реальний, живий сеанс браузера облікового запису **без** доступу
Collaborator (не фейковий токен) — у підключеному до цього сеансу браузері є
лише сесія власника (`DreamCar-vavd`); другий тестовий акаунт
(`VOLODYMYR-LUCKY`) залишається на окремому пристрої власника. Код-рівень і
автотести (StorageAuthError/StorageForbiddenError, окремо типізовані) це
покривають повністю; жива відмова РЕАЛЬНОГО (не фейкового) відкликаного
токена — ні. Недійсний токен (немає сесії/синтаксично зламаний) і чинний
токен без прав Collaborator — це два РІЗНІ шляхи коду, перевірено лише
перший. **Одна необхідна дія власника:** відкрити на тому пристрої з
`VOLODYMYR-LUCKY` (без Collaborator-доступу) `/panel/leads`, `/panel` і
draft-preview на Preview, надіслати скріншоти результатів; окремо —
спробувати зберегти зміну через Keystatic і підтвердити відсутність нового
коміту. Порожня сторінка Keystatic сама собою НЕ доказ заборони запису —
потрібна саме спроба зберегти.

Після успіху — окреме рішення власника про активацію `content-guard.yml` у
`.github/workflows/` + ruleset (той самий документ §1.5).
