# Протокол реальної hosted-перевірки панелі

Виконується **після** погодженого підключення GitHub App
(`docs/PANEL-hosting-and-approvals.md` §3), на **Preview**-деплої гілки
`codex/admin-panel-spike`. Production і `main` не залучені.

**Не активувати** workflow, що переносить контент у `main`
(`content-guard.yml`), до завершення цього протоколу — перша перевірка має
лишитися повністю ізольованою (`PANEL_CONTENT_BRANCH` веде в окрему гілку, не
в `main`).

**Критерій приймання hosted-режиму:** кроки 1–13 — ✅, і `main` за весь час не
змінився (`git log origin/main` до/після — однаковий). **10 із 13 — ✅, 3 —
⚠️** (див. колонку стану); `main` незмінна протягом усього приймання
(`ce1977af`, звірено багаторазово).

**Один необхідний крок власника** для закриття 3/10/12 наживо: відкрити
Preview на двох існуючих тестових сесіях (`DreamCar-vavd` + вже
авторизований `VOLODYMYR-LUCKY`, зараз без Collaborator-доступу) і надіслати
скріншоти (а) `/panel/leads` у сесії `VOLODYMYR-LUCKY` (очікується відмова),
(б) публікації однієї тестової картки в одній вкладці, потім спроби
публікації тієї самої картки застарілою версією в іншій вкладці того самого
акаунту (очікується повідомлення про конфлікт, не тихий перезапис).

Після успіху — окреме рішення власника про активацію `content-guard.yml` у
`.github/workflows/` + ruleset (той самий документ §1.5).
