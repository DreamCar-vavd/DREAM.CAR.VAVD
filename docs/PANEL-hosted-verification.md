# Протокол реальної hosted-перевірки панелі

Виконується **після** погодженого підключення GitHub App
(`docs/PANEL-hosting-and-approvals.md` §3), на **Preview**-деплої гілки
`codex/admin-panel-spike`. Production і `main` не залучені.

**Не активувати** workflow, що переносить контент у `main`
(`content-guard.yml`), до завершення цього протоколу — перша перевірка має
лишитися повністю ізольованою (`PANEL_CONTENT_BRANCH` веде в окрему гілку, не
в `main`).

Позначки результату: ✅ пройдено · ❌ ні · ⚠️ з відхиленням.

| # | Крок | Очікуваний результат | Як перевірити |
|---|---|---|---|
| 1 | **Вхід власника** | `/keystatic` → Sign in with GitHub → Authorize → список колекцій; `/panel` → дашборд | відкрити обидві сторінки, побачити 6 розділів у `/panel` |
| 2 | **Вхід помічника** | те саме у другому браузері / акаунті (роль Write) | помічник відкриває `/keystatic`, бачить ті самі колекції |
| 3 | **Відмова сторонньому** | акаунт БЕЗ доступу до репо: після Authorize — помилка «repo not found» / порожньо, редагувати не може | третій акаунт (або приватне вікно) → `/keystatic` → Sign in |
| 4 | **Створення синтетичного матеріалу** | нова картка (напр. послуга `zzz-test`) зберігається | Keystatic → Послуги → Create → заповнити 3 мови → Save |
| 5 | **Збереження через реальний GitHub** | Save робить коміт у гілку `PANEL_CONTENT_BRANCH` (не `main`) | GitHub → гілки → бачити новий коміт з файлом `services/zzz-test.json` |
| 6 | **Мовні підтвердження** | `/panel` → картка показує 3 мови «Потребує перевірки» → «Позначити перевіреним» × 3 → «Перевірено»; повторне збереження тексту знову «Потребує перевірки» | клацнути по кожній мові, потім змінити текст у Keystatic і оновити `/panel` |
| 7 | **Актуальна чернетка з новими фото** | `/panel` → «Переглянути чернетку на сайті» показує `zzz-test` та нове фото, яких немає в опублікованому | відкрити draft-preview, знайти картку |
| 8 | **Тестова публікація за конкретним SHA** | «Опублікувати зміни» на `zzz-test` → `published.json` у гілці контенту оновлюється; банер стану показує збірку Preview за цим SHA | `/panel` → Опублікувати → дочекатися «✅ на тестовому сайті»; звірити SHA у банері з гілкою |
| 9 | **Правильний deployment** | банер каже саме «на тестовому сайті», НЕ «в ефірі»; `environment` = Preview | подивитися текст банера + `deployStatus` |
| 10 | **Конфлікт двох редакторів** | обидва відкрили `/panel`; A публікує `zzz-test`; B (стара версія) публікує ту саму картку → **повідомлення про конфлікт + кнопка «Оновити»**, без тихого перезапису | двоє одночасно, B тисне «Опублікувати» після A |
| 11 | **Відкликання доступу** | у помічника відкликати App (Authorized GitHub Apps → Revoke) або прибрати з Collaborators | виконати, потім крок 12 |
| 12 | **Немає доступу до чернеток після виходу** | помічник оновлює `/panel` і draft-preview → «Сесію завершено або відкликано», редагування недоступне | оновити обидві сторінки у браузері помічника |
| 13 | **Прибирання** | видалити синтетичну картку в Keystatic + прибрати з `published.json` (Unpublish у `/panel`), звірити, що гілка контенту не має тестового сміття | Keystatic delete + `/panel` «Прибрати з сайту» |

**Критерій приймання hosted-режиму:** кроки 1–13 — ✅, і `main` за весь час не
змінився (`git log origin/main` до/після — однаковий).

Після успіху — окреме рішення власника про активацію `content-guard.yml` у
`.github/workflows/` + ruleset (той самий документ §1.5).
